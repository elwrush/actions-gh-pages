# Git Workflow Skill Architecture

This document explains how the `00-manage-git-workflow` skill is constructed and how it standardizes Git interactions across the project.

## 1. Skill Structure

The Git skill follows the standard **Skills-based architecture** used in this project. It is located at `skills/00-manage-git-workflow/`.

```text
skills/00-manage-git-workflow/
├── SKILL.md        # The authoritative instruction set (The Brain)
└── scripts/        # Deterministic execution logic (The Hands)
    └── git_workflow.py
```

## 2. The Instruction Layer (`SKILL.md`)

The `SKILL.md` file defines the **Agent Workflow**. It uses specific tags (`<AGENT_WORKFLOW>`) to guide the Gemini CLI through a series of logical steps:

1.  **Context Loading:** It defines Stage 0 (Maintenance) as the starting point.
2.  **Step-by-Step Procedures:** It explicitly links human-readable goals (e.g., "Release") to specific programmatic commands.
3.  **Governance:** It enforces "Iron Laws," such as the mandatory use of annotated tags for major updates.

## 3. The Execution Layer (`git_workflow.py`)

To ensure reliability and minimize "LLM guessing," the skill delegates complex Git operations to a Python script. This script handles:

*   **Routine Commits:** Automatically staging all files (`git add .`) before committing.
*   **Annotated Releases:** Creating structured tags (`git tag -a`) with version numbers and descriptions.
*   **Remote Synchronization:** Managing the sequence of `pull` and `push --tags` to keep the local and remote repositories in sync.
*   **Safety Checks:** Providing a `status` command that summarizes current branch state, recent history, and the last known tag.

## 4. Why This Architecture?

*   **Precision:** Git commands (like creating annotated tags) have specific syntax that can be error-prone when generated by an LLM. The script makes these operations deterministic.
*   **Token Efficiency:** Instead of Gemini CLI reading a 50-line Git manual every time it wants to commit, it simply reads a one-line instruction to call the script.
*   **Standardization:** Every developer or agent using this project will follow the exact same release and sync patterns, ensuring a clean and searchable repository history.

## 5. Usage in Session

When asked to "Commit" or "Release," the agent should:
1.  Consult the `SKILL.md` for the correct command.
2.  Run the corresponding `python skills/00-manage-git-workflow/scripts/git_workflow.py` command with the appropriate arguments.
3.  Verify the output to ensure the operation was successful.
